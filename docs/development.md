# 开发状态与约束

## 当前范围

已实现统一 Qt Widgets 宿主、托盘、中文设置、共享浅深主题，以及启动器、剪贴板、手势、黑屏遮挡的主要运行链。另有自动更新、GitHub Actions、当前用户登录自启、受限管理员辅助进程，以及 RTF/可序列化 MIME 格式保存。具体使用与限制见 [系统集成与数据](system-integration.md)。

仍需完成或扩大验证的项目：

- 真实 UAC 同意/取消、管理员窗口回贴/右键/手势，以及注销再登录自启的桌面验证；普通 CTest 只验证隔离注册表和禁止输入的辅助进程。
- 混合 DPI、多显示器、实体鼠标/键盘与长时间运行矩阵。
- 手势复杂路径的全部旧行为对等性和更多外观参数。hua、BlackLock 配置迁移已明确不在范围内。
- 黑屏的睡眠/唤醒、热插拔、异常注入与完整应急路径。
- 正式数据根、真实 Hopy 历史/HLaunch 启动项只读导入和跨机器部署。MT 自启只管理自身注册，不接管旧工具的启动项。
- 真实跨版本在线更新；v0.1.0 为首个公开版本，隔离更新测试不代表已完成两个正式版本之间的升级验收。

单测、隔离预览、真实桌面输入、干净机器部署和正式发布应分别记录，不能互相替代。原始本机日志、历史截图和带机器路径的开发记录保留在被忽略的 `docs/ai/`、`out/` 和原型 `evidence/` 中，不属于公开源码包。

CI 使用 Windows Server 2022，它没有 Windows 11 的 DWM 圆角接口：专用圆角测试明确跳过，菜单交互和布局继续检查。Windows 11 上保留完整 DWM 断言；CI 通过不代表已验证 Windows 11 的所有桌面效果。

## 架构

- `mt_core`：设置、持久化、领域模型、识别与版本解析。
- `mt_platform`：Windows 原生能力、资源所有权、进程与更新安装助手。
- `mt_updates`：异步版本检查和下载，系统 Schannel TLS。
- `mt_ui`：Qt Widgets、统一 QPalette/QSS 和主题。
- `mt`：唯一 QApplication、托盘、全局快捷键与模块生命周期。

模块独立启停，不创建自己的托盘、自启项或应用事件循环。数据库连接在所属线程创建、使用和销毁。输入钩子回调不做磁盘、网络或 Shell 操作；后台结果必须受对象生命周期与代次限制。

## 界面约定

- 品牌显示为 **MT**；EXE、命名空间、资源前缀等技术标识为小写 `mt`。
- 全部界面中文，系统字体，共享 `resources/theme/theme.json` 的浅色、深色和系统跟随主题。
- 正式产品 Logo 已于 2026-10-29 确认为 `resources/logo.ico`；EXE、应用窗口和托盘共用此文件，不采用设计探索中的其他候选稿。
- 功能图标来自 Lucide 0.460.0（ISC），没有合适图标时才考虑 Tabler（MIT），不手绘来源不明的图标。产品 Logo 不属于功能图标。
- 启动面板默认 4×7，可配置 3–20 行列；保留底部分类、固定空槽和隐藏附属搜索。
- 剪贴板以历史为主体，搜索默认收起，分类图标可取消；无“全部”按钮。收藏/置顶/删除常驻，序号与时间分开，不增加来源采集。
- Windows 11 DWM 提供不透明面板和菜单的圆角、边框和阴影；整窗不透明度可调，不恢复透明背景自绘主窗口阴影或硬裁切。
- 手势与黑屏在统一设置中配置，无独立管理面板。手势轨迹只是必要局部绘制。

## 开发和数据边界

所有业务代码全新编写；旧 Hopy、HLaunch、hua、BlackLock 仅为只读行为和格式参考。运行验证使用独立数据目录，不修改旧应用、自启或真实数据。正式用户数据的格式变更需设计兼容与恢复方案，失败时不得删除旧库或覆盖为空配置。

导入范围仅为 Hopy 历史（及图片、HTML 附属内容）和 HLaunch 分类/启动项（含必要快捷方式）；不迁移旧工具偏好、自启、hua 规则或 BlackLock 密码。现有 MT 历史数据库从 schema 1 升至 2 前创建一致性备份；未知版本或无版本标记的非空库拒绝写入。

当前采用 C++23、CMake、静态 Qt、静态 CRT，不引入 QML、WinUI、WebView 或动态业务插件。第三方原生 C 库可保留。构建步骤见 README；更新和发布分别见 `updating.md`、`releasing.md`。
