# 软件更新

来源固定为 `Hunlongyu/mt` 的 GitHub Releases。当前版本来自 CMake；仅接受 `vX.Y.Z` 正式版本，忽略草稿、预发布、同版本和较低版本。没有 Release 时显示“暂时没有可用的正式发布版本”。

更新资产固定为 `mt.exe`，下载地址必须与发布标签和文件名一致。已发布 v0.1.0 只识别旧资产名 `mt-windows-x64.exe`，首次切换需手动下载新版本；此后的版本可继续自动更新。安装仍保留用户当前的 EXE 文件名。

## 生命周期

1. 普通模式启动 30 秒后、之后每 24 小时检查一次；`autoCheckUpdates` 控制后台检查。隔离预览不联网。
2. 关于页可手动检查、下载或取消。网络错误只更新状态，后台检查不弹出阻塞对话框；发现新版本时显示一次托盘通知。
3. Qt Network 与 Windows Schannel 保留系统 TLS 验证。API 地址固定；下载只接受本仓库 Release 地址及 GitHub 官方资产域名的 HTTPS 重定向，最多 5 次。
4. 元数据上限 1 MiB，EXE 上限 200 MiB；15 秒无传输超时，检查总时限 60 秒，下载总时限 10 分钟。流式写入临时目录，核验资产大小和 GitHub API 的 SHA-256。失败或取消丢弃未完成下载。
5. 用户确认“安装并重启”后，把当前可信 EXE 复制为安装助手。助手再次检查下载文件大小、SHA-256、PE 签名和 x64 架构。
6. 助手验证父进程 PID、创建时间、路径，取得按程序路径划分的互斥锁。握手后宿主先断开管理员辅助连接并确认辅助进程退出，再自行退出并关闭模块；辅助进程未退出时取消安装，避免同一个 EXE 被占用。安装助手最多等待宿主 45 秒，不强行终止宿主。宿主握手超时会写入取消标记，助手不再安装。
7. `ReplaceFileW` 替换 EXE 并保留旧文件，保留当前 EXE 的路径和文件名（包括中文、空格），启动新版本时传回原 `--data-dir`。新版本和回退重启均显式使用正常窗口方式；是否启动时显示面板仍由应用设置决定，不继承安装助手的隐藏窗口方式。替换失败、退出后再次校验失败或不能创建新进程时尝试恢复/重启旧程序；新程序自身启动失败不等于进程创建失败，备份仍保留供恢复。
8. 新版本进入事件循环后写入启动确认。普通启动延迟检查同目录中属于当前 EXE 的已完成更新，只清理临时 `updater.exe`；忙碌的助手留待下次启动处理。未完成、未确认、失败或属于其他程序的暂存目录均不清理，`previous.exe` 和诊断文件保留。

不修改设置、启动项或旧工具数据。黑屏期间禁止安装，未保存设置需先处理。程序目录不可写时说明原因并保留当前程序，不请求管理员权限。

## 分层与恢复

- `ReleaseInfo`：版本、元数据和可信 URL 校验。
- `UpdateService`：异步网络、进度、取消、临时文件与状态，由宿主拥有。
- `UpdateInstaller`：Windows 进程身份、互斥、EXE 校验、替换与重启。
- EXE 旁的 `.mt-update-<UUID>` 是安装暂存目录；`previous.exe` 为原程序，`error.txt` 记录失败原因，`startup.ok` 表示新版本完成初始化并进入事件循环，包含进程、启动方式和原生可见窗口数量的诊断。启动时隐藏面板时可见窗口数可以为零。
- 对外仍是一个静态 EXE，不分发独立更新器或更新脚本；临时助手由当前已信任的 EXE 自行复制，成功启动后清理。

回退时先退出 MT，再将对应 `previous.exe` 复制为原来的 `mt.exe`，保留数据目录。不要删除数据库或用空配置覆盖错误配置。

当前剪贴板库使用 schema 2。若退回只认识 schema 1 的旧程序，需先保留完整当前数据目录，再按 [数据库恢复说明](system-integration.md#数据库升级与恢复) 使用升级前备份；仅回退 EXE 不会把数据库自动降级。

当前信任 GitHub 仓库发布权限和 HTTPS，SHA-256 校验下载完整性；尚无独立签名密钥或 Authenticode 发布签名。

`scripts/verify-update.ps1` 在独立目录验证成功替换、中文空格文件名、备份与启动确认、隐藏助手重启出的原生窗口可见、完成后的助手清理，以及错误 SHA-256、EXE 被占用和宿主取消时保留原文件。新旧程序均以预览模式运行，数据文件保持不变；它不等同于已发布版本之间的真实在线升级验证。
